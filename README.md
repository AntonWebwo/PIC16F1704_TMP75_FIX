## 📖 Описание

Это полностью переработанная, высокопроизводительная прошивка для микроконтроллера **PIC16F1704**, используемого на хеш-платах майнеров серии **Bitmain Antminer S19** (S19 Pro, S19j, S19 XP и др.).

Прошивка решает ключевые проблемы оригинального ПО: нестабильную работу I2C при высоких скоростях, конфликты адресации при подключении к тестерам и отсутствие гибкости в управлении питанием. Она обеспечивает надежную связь как с оригинальной контрольной платой (Master Board), так и со сторонними тестерами (например, STASIC Tech).

### ✨ Ключевые особенности

*   **⚡ Высокая скорость I2C:** Реализована через аппаратные прерывания (Interrupts) и бит `BOEN`, что позволяет обрабатывать быстрые пакетные передачи (до 400kHz+) без потерь данных.
*   **🎯 Универсальная адресация:** Автоматическое определение адреса при старте на основе состояния пинов **RC3, RC4, RC5** (A0, A1, A2).
    *   Работает с контрольными платами (где уровни задаются слотом).
    *   Работает с тестерами (где пины могут быть подтянуты или висеть в воздухе).
*   **🔄 Soft Reset:** Команда `0x07` выполняет мгновенный программный сброс состояния без перезагрузки микроконтроллера, исключая задержки и ошибки таймаута на стороне мастера.
*   **🌡️ Умный опрос температуры:** Реализован механизм **Fallback** для датчиков TMP75/LM75A. Если основной датчик не отвечает, система автоматически опрашивает резервные адреса.
*   **🔋 Управление питанием:** Корректная обработка команд включения/выключения питания ASIC (`0x15`).
*   **📊 Мониторинг ADC:** Чтение напряжения с канала AN6 (RC2) с высокой точностью.

## 🛠 Технические детали

### Логика определения адреса (Chain ID)

При включении питания PIC считывает состояние пинов RC3-RC5 и формирует свой I2C адрес по формуле:
`Address = 0x20 + (RC3 | RC4<<1 | RC5<<2)`

| RC5 (A2) | RC4 (A1) | RC3 (A0) | Chain ID | I2C Address | Примечание |
| :------: | :------: | :------: | :------: | :---------: | :--------- |
| 0 | 0 | 0 | 0 | **0x20** | Стандартный слот / Тестер (GND) |
| 0 | 0 | 1 | 1 | **0x21** | Слот 1 |
| 0 | 1 | 0 | 2 | **0x22** | Слот 2 |
| ... | ... | ... | ... | ... | ... |
| 1 | 1 | 1 | 7 | **0x27** | Слот 7 / Тестер (VCC) |

> **Важно:** Прошивка не управляет пинами RC3-RC5 после старта (они остаются входами High-Z), что позволяет контрольной плате или тестеру свободно менять уровни для адресации EEPROM.

### Карта команд протокола

Полная эмуляция оригинального протокола Bitmain с расширенным функционалом.

| Команда | Название | Описание | Ответ (Пример) |
| :-----: | :------- | :------- | :---- |
| `0x01` | `SET_PIC_FLASH_POINTER` | Установить маркер в памяти Flash (Заглушка) | `01 00` |

## 📊 Интерпретация данных (Data Interpretation)

Все ответы PIC-контроллера следуют строгому формату с контрольной суммой. Ниже приведены примеры разбора наиболее важных команд.

### 1. Чтение напряжения питания (Команда `0x3A`)

Эта команда возвращает сырое значение 10-битного АЦП (ADC), подключенного к делителю напряжения на хеш-плате.

**Формат ответа:**
`[Len] [Cmd] [Status] [ADC_Hi] [ADC_Lo] [Checksum_Hi] [Checksum_Lo]`

**Пример ответа:**
```text
07 3a 01 02 3d 00 81
```

**Разбор:**
*   `07`: Длина пакета.
*   `3a`: Код команды.
*   `01`: Статус успеха.
*   `02 3d`: Значение ADC (Hi byte `0x02`, Lo byte `0x3D`).
*   `00 81`: Контрольная сумма.

**Расчет напряжения:**
1.  Объедините байты в одно число:
    $$ ADC_{raw} = (Hi \times 256) + Lo $$
    $$ ADC_{raw} = (0x02 \times 256) + 0x3D = 512 + 61 = 573 $$

2.  Примените коэффициент преобразования (экспериментально подобран для S19/NBS1902):
    $$ V_{input} = ADC_{raw} \times 0.02438 $$
    $$ V_{input} = 573 \times 0.02438 \approx 13.97 \text{ V} $$

**Python функция для конвертации:**
```python
def adc_to_voltage(adc_raw):
    """
    Преобразует сырое значение ADC (0-1023) в напряжение входа хеш-платы.
    """
    COEFFICIENT = 0.02438
    return round(adc_raw * COEFFICIENT, 2)

# Пример использования:
adc_hi = 0x02
adc_lo = 0x3d
adc_raw = (adc_hi << 8) | adc_lo
voltage = adc_to_voltage(adc_raw)
print(f"Напряжение на входе: {voltage} V") # Вывод: 13.97 V
```

### 2. Чтение температуры датчиков TMP75 (Команда `0x3C`)

Эта команда считывает данные с цифровых датчиков температуры TMP75/LM75A по шине I2C.

**Формат ответа (успех):**
`[Len] [Cmd] [Status] [Temp_Int] [Temp_Frac] [Reserved] [Checksum]`

**Пример ответа:**
```text
07 3c 01 19 00 00 5d
```

**Разбор:**
*   `07`: Длина пакета.
*   `3c`: Код команды.
*   `01`: Статус успеха (датчик найден).
*   `19`: Целая часть температуры (в Hex).
*   `00`: Дробная часть (старшие биты).
*   `00`: Резервный байт.
*   `5d`: Контрольная сумма.

**Расчет температуры:**
Датчики TMP75 передают температуру в 12-битном формате. Старший байт (`Temp_Int`) содержит целую часть со знаком, а старшие 4 бита младшего байта (`Temp_Frac`) — дробную часть.

1.  **Целая часть:**
    $$ T_{int} = \text{Temp\_Int (Hex)} $$
    $$ T_{int} = 0x19 = 25^\circ\text{C} $$
    *(Если значение > 127, то это отрицательная температура в дополнительном коде).*

2.  **Дробная часть:**
    Младший байт содержит дробную часть в старших 4 битах. Каждый бит весит $0.0625^\circ\text{C}$.
    $$ T_{frac} = (\text{Temp\_Frac} >> 4) \times 0.0625 $$
    В примере `0x00`, значит дробная часть равна 0.

    *Пример с дробной частью:* Если бы ответ был `19 80`, то:
    $$ 0x80 = 1000 0000_2 $$
    Старшие 4 бита: `1000` = 8.
    $$ T_{frac} = 8 \times 0.0625 = 0.5^\circ\text{C} $$
    Итоговая температура: $25.5^\circ\text{C}$.

**Python функция для конвертации:**
```python
def parse_tmp75_temp(temp_int_hex, temp_frac_hex):
    """
    Парсит температуру из байтов ответа команды 0x3C.
    """
    # Целая часть (со знаком)
    t_int = int(temp_int_hex, 16)
    if t_int > 127:
        t_int -= 256 # Преобразование дополнительного кода для отрицательных температур
        
    # Дробная часть (старшие 4 бита младшего байта)
    # Вес одного бита = 0.0625 градуса
    t_frac_bits = (int(temp_frac_hex, 16) >> 4) & 0x0F
    t_frac = t_frac_bits * 0.0625
    
    total_temp = t_int + t_frac
    return round(total_temp, 2)

# Пример использования:
# Ответ: 07 3c 01 19 80 00 ...
temp = parse_tmp75_temp("19", "80")
print(f"Температура чипа: {temp} °C") # Вывод: 25.5 °C
```

### 3. Версия прошивки (Команда `0x17`)

**Формат ответа:**
`[Len] [Cmd] [Version] [Reserved] [Checksum]`

**Пример ответа:**
```text
05 17 ab 00 bd
```

**Разбор:**
*   `ab`: Версия прошивки (Hex). В данной прошивке `0xAB` соответствует авторской сборке Anton Vinogradov.
*   `bd`: Контрольная сумма (`05 + 17 + AB + 00 = 0xC7`? Нет, в коде используется `0xBD` для другой версии или расчета. Всегда проверяйте актуальную сумму в логе).

*(Примечание: В текущей версии прошивки контрольная сумма для `05 17 AB 00` рассчитывается как `0xC7`. Если вы видите `0xBD`, возможно, версия байта FW изменена).*

### 4. Обработка ошибок

Если команда выполнена с ошибкой или датчик не найден, статусный байт будет отличаться от `0x01`.

*   **Статус `0x00`**: Ошибка выполнения (например, таймаут I2C при опросе TMP75).
*   **Ответ `FF FF`**: Ошибка контрольной суммы входящего пакета или неверный формат команды.
*   **Команда `0x3C` при отсутствии датчика**:
    ```text
    07 3c 00 00 00 00 43
    ```
    *   `00`: Статус ошибки (датчик не ответил).
    *   `00 00`: Нулевые значения температуры.

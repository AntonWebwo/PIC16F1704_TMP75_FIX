# Прошивка PIC16F1704 с фиксом для датчиков температуры Antminer S19

Профессиональная, полностью переписанная прошивка для PIC-контроллера **PIC16F1704**, который используется на хеш-платах **Bitmain Antminer S19**. Главная цель этого проекта — решение проблемы с неисправными датчиками температуры TMP75, которые часто приводят к остановке майнинга.

## Проблема

На многих хеш-платах Antminer S19 со временем выходят из строя один или несколько из четырёх датчиков температуры TMP75. Стандартная прошивка PIC-контроллера при инициализации обнаруживает ошибку чтения даже одного неисправного датчика и полностью останавливает запуск майнинг-процесса. Это вынуждает мастеров по ремонту тратить время на поиск и замену неисправного датчика или установку "обманки" на первый датчик с адресом `0x48`.

## Решение: Интеллектуальный Fallback

Данная прошивка предлагает элегантное и надёжное программное решение, которое делает физическое вмешательство необязательным.

Основная логика работы:
1.  Контроллер последовательно опрашивает все 4 датчика температуры.
2.  Если какой-либо датчик (например, на адресе `0x49`) не отвечает, прошивка не выводит ошибку. Вместо этого, она автоматически опрашивает резервный (fallback) датчик на адресе `0x48`.
3.  Полученное от резервного датчика значение температуры подменяется в ответе для неисправного датчика. Таким образом, управляющая плата "видит" корректные данные и продолжает работу в штатном режиме.
4.  **Безопасность превыше всего:** Если неисправны **все 4 датчика**, контроллер вернёт ошибку чтения. Это критически важный механизм защиты, который предотвращает перегрев и выход платы из строя.

## Ключевые особенности

*   **Интеллектуальный Fallback:** Игнорирование неисправных датчиков температуры и использование данных с рабочего.
*   **Повышение отказоустойчивости:** Майнинг продолжается даже с 1, 2 или 3 неисправными датчиками.
*   **Защита от перегрева:** Гарантированная остановка в случае отказа всех датчиков.
*   **Стабильность:** Код прошивки полностью переписан с нуля для максимальной надёжности.
*   **Программный I2C (BitBang):** Реализована собственная, более надёжная шина I2C для общения с датчиками.
*   **Расширенный протокол:** Добавлены команды для более глубокой диагностики и управления.
*   **Утилита для тестирования:** Поставляется Python-скрипт `send_pic_cmd.py` для удобного взаимодействия с контроллером.

## Утилита для тестирования `send_pic_cmd.py`

Для удобства отладки и тестирования в проект включен скрипт `send_pic_cmd.py`. Он позволяет отправлять команды PIC-контроллеру без необходимости вручную формировать пакеты (добавлять преамбулу `0x55 0xAA`, длину и рассчитывать контрольную сумму). Скрипт делает всё это автоматически.

**Требование:** Для прямого доступа к I2C-шине необходимы права суперпользователя (`sudo`).

### Параметры скрипта:

*   `-b`, `--bus`: Номер I2C-шины (например, `1`).
*   `-a`, `--addr`: I2C-адрес PIC-контроллера (по умолчанию `0x20`).
*   `-w`, `--write`: Данные для записи (команда и её аргументы в hex-формате через пробел).
*   `-r`, `--read`: Количество байт, которые нужно прочитать в ответ.
*   `--crc`: Тип контрольной суммы. `16` для CRC16. По умолчанию используется Checksum-8.
*   `--json`: Вывести ответ в удобном формате JSON.

## Протокол и Поддерживаемые Команды

Обмен данными с контроллером происходит по стандартной шине I2C.

**Формат пакета:** `[0x55, 0xAA, size, ...cmd, chk]`
*   `0x55, 0xAA`: Преамбула.
*   `size`: Общая длина пакета (включая `cmd` и `chk`).
*   `cmd`: Тело команды (от 1 байта).
*   `chk`: Контрольная сумма (Checksum-8).

---

### `0x3C`: Чтение температуры с датчика

Это основная команда для получения данных о температуре. Она автоматически использует fallback-логику.

*   **Запрос:** `3C <addr> 02 00`, где `<addr>` - адрес датчика (`48`, `49`, `4A` или `4B`).
*   **Пример (чтение датчика `0x4A`):**
    ```bash
    sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 3c 4a 02 00 -r 7 --json
    ```
*   **Успешный ответ:**
    ```json
    {"status": "ok", "response": "07 3c 01 17 08 00 63", "bytes": [7, 60, 1, 23, 8, 0, 99]}
    ```
    Здесь `17 08` (23.5°C) — это температура. `01` означает успешное чтение.
*   **Ответ при отказе всех датчиков:**
    ```json
    {"status": "ok", "response": "07 3c 00 00 00 00 43", "bytes": [7, 60, 0, 0, 0, 0, 67]}
    ```
    Здесь `00` после `3c` сигнализирует об ошибке чтения.

### `0x17`: Получение версии прошивки

*   **Запрос:** `17 00`
*   **Пример:**
    ```bash
    sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 17 00 -r 5 --json
    ```
*   **Ответ:**
    ```json
    {"status": "ok", "response": "05 17 ab 00 c7", "bytes": [5, 23, 171, 0, 199]}
    ```
    Где `ab` (`0xAB`) — это версия прошивки (Антон Виноградов).

### `0x15`: Управление питанием чипов

Включает или выключает питание ASIC-чипов на плате.

*   **Запрос на включение:** `15 01`
*   **Запрос на выключение:** `15 00`
*   **Пример:**
    ```bash
    sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 15 01 -r 2 --json
    ```

### `0x07`: Перезагрузка PIC-контроллера

*   **Запрос:** `07 00`
*   **Пример:**
    ```bash
    sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 07 00 -r 2 --json
    ```
    Контроллер вернёт `07 01` и перезагрузится.

### `0x3B`: Прямая запись в регистр датчика

Позволяет напрямую записывать данные в регистры любого I2C-устройства на BitBang-шине.

*   **Запрос:** `3b <addr> <reg> <value>`
*   **Пример (запись `00` в регистр `00` датчика `0x48`):**
    ```bash
    sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 3b 48 00 00 -r 2 --json
    ```

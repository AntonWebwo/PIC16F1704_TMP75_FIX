## С чем боремся? (Проблема)

Все мы знаем эту боль. На платах Antminer S19 (особенно на некоторых ревизиях) со временем "отваливаются" датчики температуры TMP75. Их там четыре. Стоковая прошивка PIC'а, обнаружив при запуске хотя бы один неисправный датчик, впадает в панику и не даёт майнеру запуститься.

В итоге, нам, мастерам, приходилось тратить время: вызванивать дохлый датчик, менять его, а то и вовсе вешать "обманку" на первый датчик (`0x48`), чтобы плата завелась.

## И как побеждаем? (Решение)

Моя прошивка делает всё это ненужным. Я внедрил **интеллектуальный fallback-механизм**:

1.  При старте контроллер, как и раньше, опрашивает все четыре датчика.
2.  Если какой-то из них не отвечает (например, по адресу `0x49`), прошивка **не выдаёт ошибку**. Вместо этого, она по-тихому обращается к заведомо рабочему резервному датчику (`0x48`).
3.  Затем она берёт температуру с рабочего датчика и подставляет её в ответ для того, который "умер". В итоге, управляющая плата видит четыре корректных значения и спокойно запускает майнинг.
4.  **Безопасность превыше всего!** Если вдруг окажется, что **умерли все четыре датчика**, вот тогда прошивка честно скажет "всё плохо" и вернёт ошибку. Это защита от дурака и перегрева.

**Итог:** плата работает, даже если 1, 2 или 3 датчика вышли из строя. Никакой пайки.

## Скальпель для PIC'а: Утилита `send_pic_cmd.py`

Чтобы не мучиться с ручным формированием пакетов, я набросал простой Python-скрипт. Он сам добавляет преамбулу, считает длину и контрольную сумму. Вам нужно только указать команду и её параметры.

**Важно:** Для прямого доступа к шине I2C нужны права `sudo`.

### Как пользоваться:

*   `-b`, `--bus`: Номер I2C-шины (например, `1`).
*   `-a`, `--addr`: Адрес PIC'а (обычно `0x20`).
*   `-w`, `--write`: Команда и её аргументы в hex-формате.
*   `-r`, `--read`: Сколько байт ждём в ответ.
*   `--json`: Делает вывод красивым и читаемым.

## Разбираем протокол по косточкам

Все команды используют **Checksum-8** для проверки целостности. Скрипт считает её сам.

---

### `0x3C`: Чтение температуры (самая важная команда)

Эта команда опрашивает датчик и использует fallback-логику, если он неисправен.

*   **Запрос:** `3c <addr> 02 00`, где `<addr>` — адрес датчика (`48`, `49`, `4a` или `4b`).

*   **Пример: читаем датчик `0x4a`**
    ```bash
    sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 3c 4a 02 00 -r 7 --json
    ```

*   **Как читать ответ:**
    Предположим, получили `{"response": "07 3c 01 17 08 00 63"}`.
    *   `07`: Длина ответа.
    *   `3c`: Команда, которую выполняли.
    *   `01`: **Статус. `01` = Успех.**
    *   `17 08`: **Температура.** Это два байта: `temp_int` и `temp_frac`.
        *   `0x17` — это целая часть в HEX. `0x17` = 23 градуса.
        *   `0x08` — это дробная часть. Чтобы получить градусы, умножаем её на `0.0625`. `8 * 0.0625 = 0.5`.
        *   **Итого: 23.5 °C.**
    *   `00`: Зарезервировано.
    *   `63`: Контрольная сумма ответа.

*   **Пример, если все датчики мертвы:**
    ```json
    {"response": "07 3c 00 00 00 00 43"}
    ```
    Видите `00` после `3c`? Это **статус "Ошибка"**. Значит, пора менять плату или все датчики.

### `0x3A`: Чтение АЦП (диагностика)

Эта команда читает значение со встроенного в PIC аналого-цифрового преобразователя (канал AN6, ножка RC2). Это может быть полезно для диагностики напряжения.

*   **Запрос:** `3a 00`

*   **Пример:**
    ```bash
    sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 3a 00 -r 7 --json
    ```

*   **Как читать ответ:**
    Предположим, получили `{"response": "07 3a 01 02 3d 00 81"}`.
    *   `07`: Длина.
    *   `3a`: Команда.
    *   `01`: Статус "Успех".
    *   `02 3d`: **Значение АЦП.** Это 16-битное число, старший байт вперёд.
        *   `0x023D` в HEX = `573` в десятичной системе.
    *   `00 81`: Контрольная сумма ответа.
 
       
    ```python
    def adc_to_voltage(adc_raw):
        """
        Преобразует сырое значение ADC (0-1023) в напряжение входа хеш-платы.
        Коэффициент рассчитан экспериментально для платы NBS1902 / S19.
        """
        COEFFICIENT = 0.02438
        return round(adc_raw * COEFFICIENT, 2)
    
    # Пример использования для вашего лога:
    # Ответ: 07 3a 01 02 3d 00 81
    # Hi=0x02, Lo=0x3D -> Raw = 573
    print(f"Напряжение на входе: {adc_to_voltage(573)} V") # Выведет 13.97 V
    ```

### `0x17`: Узнать версию прошивки

Позволяет убедиться, что на PIC'е залита именно эта прошивка.

*   **Пример:**
    ```bash
    sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 17 00 -r 5 --json
    ```
*   **Ответ:** `{"response": "05 17 ab 00 c7"}`. Байт `ab` — это и есть версия. `0xAB` = Антон Виноградов.

### `0x15`: Включить/выключить чипы

Управляет питанием ASIC-чипов на плате.

*   **Включить:** `sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 15 01 -r 2 --json`
*   **Выключить:** `sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 15 00 -r 2 --json`

### `0x07`: Перезагрузить PIC

Просто перезагружает контроллер.

*   **Пример:** `sudo python3 send_pic_cmd.py -b 0 -a 0x20 -w 07 00 -r 2 --json`
